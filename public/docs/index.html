Introduction

Open source built the world. The market looked away.

GitFi is a launchpad and exchange for repositories. Not for a founder's slide deck, not for a private company — for the public work that developers already ship.

A repository is a real asset with real users, real maintenance costs and real cultural gravity. But before GitFi, the only way to “invest” in open source was to star it, sponsor it, or hope the maintainer eventually built a company around it. There was no market. There was no ownership layer. There was no way for a new repo to be discovered by people looking for the next important piece of infrastructure.

GitFi fixes that with three primitives: proof of ownership, a real market, and a shared fee. One repository becomes exactly one token. The verified owner creates it. The market discovers it. Trading settles on NEAR. The creator, the team and the people who stake the token all earn from the same activity.

The story

A builder can ship for years and still be invisible.

Imagine a developer who spends three years building a small database tool. It has two thousand stars, a few hundred forks, and is quietly used inside companies that the developer will never meet. The code is public. The impact is real. But there is no market for the work, no way for a newcomer to discover it early, and no feedback loop between the value of the repository and the person maintaining it.

The modern internet has this backwards. A project can be foundational and still have no price, no ownership, no discoverable floor. Stars are a social signal, but they don't pay for a server. A trending page can make a repo famous for a day, but it doesn't let the people who care about it participate in the upside.

“The next important open-source project probably exists already. It is just not priced, not discoverable, and not owned by the people who believe in it.”

GitFi begins with a simple question: what if every public repository could be recognised as an asset without asking the maintainer to give up control, take venture money, or rebuild their project as a company? What if recognition itself became a market — and that market paid the people doing the work?

That is the experiment. A repository gets a deed. A token gets a market. A market gets a chart, a community and a reason to care. The builder keeps the code public and earns from every trade. The trader gets a real, traceable market instead of a screenshot. The reader gets a way to discover code before the crowd.

GITFI DESIGN PRINCIPLE / 01

The problem

Four broken incentives in the open-source economy.

01

Builders are invisible

Great repositories are buried under a feed of releases and retweets. Discovery rewards marketing, not engineering. Maintainers have no direct way to turn attention into sustainable funding.

02

Attention has no ownership

Stars, forks and downloads are public signals, but nobody can own a position in the work. There is no market price, no cost basis, no way to participate.

03

Traders lack real discovery

New token launches are often disconnected from real work. There is no verifiable link between the asset and the repository behind it, so due diligence becomes guesswork.

04

Platforms capture the value

The repo creates the community, the traffic and the reputation. The platform captures the upside. The maintainer gets a badge and a thank-you.

→
GitFi's bet

If a repository can be verified, priced and traded, then discovery becomes economic. The best work can rise because people can put capital and reputation behind it — not only because an algorithm decided to show it.

The solution

One repo. One deed. One real market.

GitFi is built around three linked identities:

01

Repo

A public GitHub repository. It is the source of truth, the brand and the utility.

02

Deed

An on-chain ownership record, bound to a wallet that proved README control.

03

Market

A token and a reserve on NEAR. Buy, sell, stake, claim — all wallet-signed.

The repo and deed are joined by a single line the owner puts in their README. No OAuth, no GitHub app permissions, no custody of a GitHub account. The deed is verified against the public README and then minted on NEAR. The market is created only after that proof and after the fixed 1 NEAR launch fee is paid to the team.

!
Owner-only by design

A repo can have exactly one token, and only the wallet that proved README ownership can create it. A random wallet cannot launch a market from someone else's repository. This is enforced in the API and in the database, not just in the UI.

Why this can stand out in a crowded hackathon

Most launchpad projects stop at “mint a token and draw a chart.” GitFi connects the token to a real, verifiable artifact — a public repository — and makes the owner prove control without OAuth. That single constraint changes the trust model, the discovery model and the story. The market is not the product; the repository is. The market is how the repository becomes legible to capital.

How it works

From public code to a live market in five steps.

01

Connect a NEAR wallet

NEAR Connect + NEP-413. No email, no GitHub OAuth, no custodial account.

02

Prove the repository

Add a one-time sync line to the public README. GitFi verifies the raw file and binds the repo to your wallet.

03

Pay the launch fee

A wallet-signed transfer of 1 NEAR goes directly to the team address. The server verifies signer, receiver and amount before anything is created.

04

Create the market

The market contract creates the token market and its initial reserve. The creator becomes the market owner.

05

Trade, stake, claim

Buy or sell with NEAR. Stake tokens for fee yield. Claim creator fees. Fund bounties. Everything is signed by your wallet.

Proof of ownership

No GitHub OAuth. A cryptographic handshake through public code.

GitFi does not ask for GitHub permissions because it does not need them. Ownership is proven by the one thing only the repository owner can change: the public README.

README.mdONE LINE
GitFi.fun sync ID: GF-XXXXXXXX-XXXXXXXX · wallet your-name.testnet · repo owner/repository

The server generates a one-time challenge, fetches the raw README, checks the line, and stores a wallet-bound verification. The token, deed and market are created only after that check. The proof is bot-resistant because a public copy of the line from another repo cannot satisfy a challenge bound to your wallet, repo and nonce.

RULE 01One repo → one token

Enforced by the database and the market contract.

RULE 02One owner → one deed

A second wallet cannot claim an already-verified repo.

RULE 03Owner-only creation

Another wallet cannot launch a token from your repo.

RULE 04No free allocation

Creators buy from the market like everyone else.

Market mechanics

A real reserve, a step price, and a chart that tells the truth.

The deployed market is a NEAR-quoted step-price market. It is intentionally simple and legible: every trade has a price, a token amount and a NEAR amount recorded on-chain. The contract holds the sell reserve, tracks balances and cost basis, and emits every fill for indexing.

PRICE

Step price

Buys move the price up by one step; sells move it down. The current price is always a contract value, not an off-chain oracle.

RESERVE

Real NEAR liquidity

The contract holds a reserve that pays sellers. The reserve is visible on the market page and cannot be spent by the creator.

POSITION

Cost basis and PnL

The contract stores each account's balance and cost. The UI shows value, average entry and PnL including fees.

DISPLAY

USD marks, NEAR settlement

Trading is always in NEAR. The UI converts to USD with a live NEAR/USD quote so prices and market caps are readable.

What graduation means

The market has a curve supply. When the sold supply reaches the curve target, the market status becomes graduated: the curve stops issuing new inventory, and the existing market remains open on-chain. GitFi does not claim a third-party DEX pool exists; that is a mainnet decision, not a fake feature.

Design principles

Four rules we refuse to trade away.

01Proof over permission

A public README is enough. We do not ask for OAuth, passwords or platform approval to recognise ownership.

02One repo, one market

Scarcity is what makes the asset legible. A second wallet cannot clone a verified repo into another token.

03Real settlement

Balances, trades, reserves, staking and bounties are on NEAR. The interface may be pretty; the accounting is not a mock.

04Honest boundaries

If something is testnet, internal-ledger or not audited, the docs say so. Trust grows from clarity, not from pretending.

Vision

A world where every repository can find its market.

There are hundreds of millions of public repositories. Most will never become a company. That does not mean they have no value. It means the value is trapped in a format the market cannot read.

GitFi is a translation layer. It turns a repository into a deed, a deed into a market, and a market into a reason for the world to pay attention to the work. The long-term vision is not “a token for every repo.” It is a discovery and ownership layer for open source, where the best work can be recognised early and the people who maintain it can keep building.

Security model

What is verified, what is trusted, what is still a boundary.

01README proof is one-time and wallet-bound

A challenge is tied to a repo, wallet and nonce; replaying another project's line does not pass.

02Owner-only market creation

Only the verified wallet can create a token. Another wallet cannot launch someone else's repo.

03Real on-chain balances

Buys, sells, stakes and claims are wallet-signed contract calls. The server cannot move user funds.

04Reserve isolation

The sell reserve, creator fees, staking pool and bounty escrow are tracked separately in the contract.

05Checked math

All market arithmetic uses integer math with explicit bounds; fee splits are computed on-chain.

06Not audited yet

This is a testnet build. A mainnet deployment needs an external audit and a production owner/treasury setup.

FAQ

Questions people actually ask.

Is this a real market or a demo?

It is a real NEAR testnet market. Wallet-signed trades settle in the market contract. The testnet build is reset to an empty market state; the old seeded tokens were removed. USD values are display-only and use a live NEAR/USD quote; settlement is in NEAR.

Can someone else launch a token from my repo?

No. A repository can have one token, and only the wallet that proved README ownership can create it. The API rejects other wallets and the database enforces a single token per repo.

Do you need my GitHub password or OAuth?

No. GitFi only reads the public README. Ownership is proven by adding one temporary sync line. There is no GitHub login, no app installation and no access token.

How much does it cost to launch?

1 NEAR, paid directly to the team wallet with a wallet-signed transfer. The server verifies the transaction before creating the market. The payment transaction cannot be reused.

What does the 1.3% trade fee pay for?

0.5% to the token creator, 0.3% to the team, and 0.5% to token stakers. Creator and team shares accrue on-chain; staking rewards are pro-rata and claimable in NEAR.

Do GitHub stars create tokens or yield?

No. Stars are a discovery and credibility signal. They influence tier visibility (Seed, Rising, Viral) and help traders judge the repository, but they do not mint tokens, create yield or guarantee a price.

Why are prices shown in USD if trading is in NEAR?

NEAR is the settlement asset. USD is a familiar display layer powered by a live NEAR/USD quote. The contract always records NEAR amounts and token balances.

Is the token a NEP-141 contract?

Not yet. This testnet build keeps balances inside the market contract. Standalone NEP-141 tokens are on the mainnet roadmap; the docs do not pretend otherwise.

Glossary

Plain-language glossary.

Repo deed

The on-chain proof that a wallet controls a repository.

Settlement

The asset that actually moves when you trade. Here: NEAR.

Reserve

NEAR held by the market contract to pay sellers.

Step price

A price that moves by a fixed increment after each buy or sell.

Cost basis

The amount you paid for your current token position, tracked on-chain.

PnL

Profit and loss: current value minus cost basis.

Staker

A holder who locks tokens in the market to earn fee yield.

Graduation

The point where the curve stops issuing new inventory; the market stays open.

README proof

A one-line challenge in a public README that proves repo control.

NEP-413

A NEAR standard for wallet-signed authentication messages.
